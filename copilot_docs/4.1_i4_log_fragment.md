## As written

- `AsyncRunner.call_soon(callback)` = `__ensure_thread_and_loop()`, then `self.__loop.call_soon_threadsafe(callback)`.
- `renderer/server_window.py`: `SceneLock(Protocol)` and `VisorRcaWindow(capture, renderer, vtk_lock, reschedule)`,
  all four required.
  - `img_cols_rows` is a property and follows Section 4 steps 1–3.
  - `_apply_deferred` applies the last recorded size once, then forwards the queue in order.
  - `_placeholder` uses `round(c * 255)` of `renderer.background_rgb` at the last size `process_resize_event`
    received, or `INITIAL_WINDOW_SIZE` before any. `INITIAL_WINDOW_SIZE` is imported from `server_renderer.py`
    rather than restated, under ruling 12. Tests keep the literal `(300, 300)` (rule 10c).
- `app/trame/server_loop_bridge.py`: `ServerLoopBridge(FrameRequester)` with `RETRY_DELAY_S = 0.1` and the methods
  below. There is no `write_state`.
  - `__init__(async_runner)`: the runner is required.
  - `bind(view_handler)`: stores the handler, then calls `request_frame()`.
  - `request_frame()`: does nothing before `bind`; afterwards it calls
    `async_runner.call_soon(view_handler.schedule_render)`.
  - `retry_frame()`: does nothing before `bind` or while a retry is pending. Otherwise it marks a retry pending and
    calls `asyncio.get_running_loop().call_later(0.1, _fire_retry)`.
  - `_fire_retry()`: clears the pending mark, then calls `schedule_render()`.
- `tests/helpers/utils/locks.py`: `lock_held_by_another_thread(lock)` and `LOCK_TIMEOUT_S = 5.0`. Every wait and
  join has a timeout.
- The ruling-6 tests build the window's `ServerRenderer` with the bridge itself as its `FrameRequester`, as
  production will wire it.

## Found, not fixed

- `test_trame_server_manager.py` leaks un-awaited `_start_core` and `_stop_core` coroutines through its `MagicMock`
  runner. The number reported per session depends on garbage-collection timing (see Gates).
- `AsyncRunner.call_soon` after `dispose()` starts a fresh thread and loop, as `run_coroutine` does today
  (`__ensure_thread_and_loop`) [src]. A bridge bound to a handler from the disposed loop would then schedule onto a
  loop with no scheduler tasks. No production code calls `dispose`: the only callers are in `test_async_runner.py`
  (`dispose(` search in the earlier session; not re-run here).
- If `_apply_deferred`'s forward of one event raises, the events after it in that batch are lost. That exception
  also kills the render task (Q-8, carried to S3.1).
- The bare `window.img_cols_rows` reads in the tests are deliberate property reads. A Python linter with
  flake8-bugbear B018 would flag them; no such linter runs in the gates.

## Carried

- Whether `on_server_ready` runs on the loop thread. `bind` no longer reads `get_running_loop()`, so it no longer
  fails loudly when called off the loop. S1.6b's `test_first_frame_is_pushed` is now the only check (see 4.1_plan.md
  "For section 8").
- `retry_frame` still reads `asyncio.get_running_loop()` at call time. It runs only inside `img_cols_rows`, on the
  loop thread [src, `image_scheduler._render_frame`, per 4.1_plan.md 1.1].
- Off-screen render in CI: the first CI run of `test_first_frame_is_background` (ruling 4).
