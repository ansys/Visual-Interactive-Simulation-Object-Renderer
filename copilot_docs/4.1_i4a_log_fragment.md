## Design

- `AsyncRunner.call_later(delay_s, callback) -> None`: `self.__loop.call_soon_threadsafe(self.__loop.call_later,
  delay_s, callback)`. The registration of the delayed call is itself marshalled onto the loop thread through the
  thread-safe primitive, so the method is callable from any thread and never blocks the caller; `loop.call_later`
  called directly from a foreign thread is not thread-safe (stdlib contract) [inf].
- `ServerLoopBridge.retry_frame` calls `self._async_runner.call_later(self.RETRY_DELAY_S, self._fire_retry)` instead
  of reading `asyncio.get_running_loop()`. The `import asyncio` line is dropped; `git grep -n -F "asyncio" --
  src/ansys/visor/viewer/app/trame/server_loop_bridge.py` after the edit [run]: no match.
- Test re-pointing: the `loop` fixture and `_RecordingLoop` class are removed. `_RecordingRunner` gains
  `records: list[tuple[float, object]]` and `call_later(delay, callback)`, appending to it. The two ruling-6 tests
  (`test_two_locked_calls_leave_one_pending_retry`, `test_retry_fires_then_rearms`) take `runner` instead of `loop`
  and assert against `runner.records` instead of `loop.records`; the assertions themselves (delay `0.1`, the fired
  callback, the pending-retry count) are unchanged. The module docstring's "The running loop is replaced by a
  recording double" line is corrected to "The runner is replaced by a recording double."
- New pin: `test_call_later_runs_on_runner_thread` in `test_async_runner.py`, on the same `runner` fixture as
  `test_call_soon_runs_on_runner_thread`. It additionally measures that `call_later` returns before the delay
  elapses (`elapsed < delay_s`) and that the callback has not yet run at that point (`not ran.is_set()`), then waits
  for it and checks the thread id.
