## Deviations

- **Patch-target and fixture re-pointing (not named in the S1.5 entry).** Moving the 18 shared triggers' logging,
  the `_set_www_path` call to `settings`, and the `__trame_logger` field onto `SceneTriggerApp` left the production
  code they exercise reachable only through `ansys.visor.viewer.app.trame.scene_trigger_app`, not `local_app`. A test
  that patches a name the moved code no longer reads patches nothing live, and a mock-recording assertion on it is
  vacuous rather than a true pin. Re-pointed, on the precedent of ruling 9 (S1.2's identical logger-patch case):
  - 12 `patch("ansys.visor.viewer.app.trame.local_app.logger")` → `...scene_trigger_app.logger` in `test_local_app.py`.
  - 3 each in `test_local_app_sync_camera.py` and `test_local_app_set_projection.py`, same target → same rename.
  - 1 in `test_local_app_ui_panel_triggers.py`, 7 in `test_local_app_widget_triggers.py`, same rename.
  - 5 `patch("ansys.visor.viewer.app.trame.local_app.settings")` → `...scene_trigger_app.settings` in
    `test_visor_trame_app.py`.
  - 3 reads of `app._LocalApp__trame_logger` → `app._SceneTriggerApp__trame_logger` in `test_visor_trame_app.py`,
    because Python's name-mangling is keyed to the class whose body writes `self.__trame_logger`, which is now
    `SceneTriggerApp`.
  - Added `server.state = {}` to the `mock_server` fixture in all seven `tests/unit/app/test_local_app*.py` files
    plus `test_visor_trame_app.py`, on the convention found in the preflight table, so the new rendering-mode seed
    is observable as real dict state rather than swallowed by `MagicMock`'s auto-mocked `__setitem__`.
  - This finding and its scope were reported to the developer before being written; "Approved as proposed" covers
    this fix along with the base plan, since it is a mechanical consequence of the move the plan already specifies,
    not a new design choice.
- No other deviation. The constructor order ("seed rendering_mode, register lifecycle hooks, set headers and the
  www path") is as 5.4 states; `rendering_mode` resolves against `self`'s actual (leaf) class even while the base's
  `__init__` is still running, so the seed can read `LocalApp.rendering_mode` before `LocalApp.__init__`'s own body
  (which only sets `self._pick_geometry` before calling `super().__init__()`) has done anything else [inf, Python
  method resolution].

## As written

- `app/trame/scene_trigger_app.py` (new): `SceneTriggerApp(ABC)`, abstract `rendering_mode -> RenderingMode`
  (`@property @abstractmethod`), docstring exactly as 5.4 gives it. Carries `SceneMutationApi`, the six payload
  models, `parse_payload`, `_register_lifecycle_hooks`, `_set_headers`, `_set_www_path`, `get_visor_scene_details_json`,
  `_mutation_api`, the 17 remaining shared triggers, and `set_only_cookie`, each unchanged from `local_app.py` except
  the `parse_payload` docstring's one sentence naming "Before this decorator the handlers indexed their payloads
  directly", which named a state this module never had and was dropped.
- `__init__(self, server, get_scene_details_json, standalone, trame_logger, scene_mutation_api)`: no defaults, all
  five required, per the planning rule that a new injection point takes no default. Seeds
  `self.server.state["rendering_mode"] = self.rendering_mode.value`, then `_register_lifecycle_hooks()`,
  `_set_headers()`, `_set_www_path(standalone)`, in that order.
- `app/trame/local_app.py`: `@TrameApp() class LocalApp(SceneTriggerApp)`. Constructor keeps its signature and
  defaults (`standalone=True, trame_logger=None, pick_geometry=None, scene_mutation_api=None`), sets
  `self._pick_geometry` first, then calls `super().__init__(...)` with all five keywords. `rendering_mode` returns
  `RenderingMode.LOCAL`. Keeps `pick_geometry`, `perf_report_wasm`, `perf_report_server_update` unchanged.
- `tests/unit/app/test_scene_trigger_app.py` (new): the two pins below, plus the re-pointed test files (Deviations).
