## Deviations (from the S1.3 entry and the approved plan)

- **V1 — Pick-list pin.** Ruling 17 as given: "with the outline visible, a pixel on the outline outside the part
  returns None". Measured [run, scratch probe on a real `ServerRenderer`]: at `(267, 150)` with outline bounds
  `[-1.3, 1.3, -1.3, 1.3, -0.5, 0.5]`, an unrestricted `vtkCellPicker` hits the outline (`vtkOpenGLActor`) and
  `pick_part_at` returns `None`. An implementation **without** the pick list also returns `None` there: the hit
  outline actor maps to no node. That case therefore cannot fail if the pick list is removed. Written as given, and
  a second case added that does pin the list: outline bounds `[0, 0.5, -0.5, 0.5, 1.2, 1.5]` (an edge between camera
  and part), pixel `(150, 150)`: unrestricted picker hits the outline, `pick_part_at` returns `7`. Both are cases of
  `test_pick_part_at_skips_the_outline`. Not falsified (two-variant cap); the probe's unrestricted-picker column is
  the evidence that removing the list changes the in-front result [run].
- **V2 — Clipping in the pick.** First in-front probe returned `None` even with the pick list. Diagnosed [run]: with
  the list, `Pick` → `0`; the cell picker honours the mapper clipping plane, and `update_bounds` had re-seeded the
  cross-section plane at origin z ≈ 1.16, normal +z, clipping the whole sphere. The test moves the plane clear with
  `sync_cross_section_plane([0, 0, -5], [0, 0, 1])`.
- **V3 — Predicted delta.** Plan: +33. Landed: +34, the extra being the in-front case (V1).
- **V4 — `IRenderer.ts` form.** The contract is a `//` block under "Per-part visual state", matching the file's
  "View-level widgets" convention; a stacked JSDoc block would attach to nothing.
- **V5 — OpenGL2 import.** `server_renderer.py` imports `vtkmodules.vtkRenderingOpenGL2` so `vtkRenderWindow()`
  is the concrete window regardless of import order. Not in the entry.
- **V6 — Parity local fixture.** A copy of the seven-patch fixture body (named duplicate, ruling 12 of Section 8),
  with `cross_section_widget.plane = None` so `register_node` can hand it to the real mapper.

## By design

- **Cross-section clip with the widget off** (ruling 22). `register_node` attaches the widget plane to every
  mapper unconditionally [src, `pipeline_renderer.py`], and `ServerRenderer.set_cross_section_visibility(False)`
  only turns the widget off, so a plane dragged and then hidden keeps clipping the parts, and parts clipped away are
  not pickable (V2). The developer ruled this the intended behaviour, the same as local mode. Not a defect.
